Evidence pack

GPT models for Cathy

RFC

Problem. Cathy runs on Mastra and the AI SDK, which work with any provider, but the Worker only ever built an Anthropic model and only sent Anthropic thinking settings. Chris wants GPT 6.1 Sol and GPT 6 Astra in the model picker.

Design.

  • providerFor(id) in models.ts: gpt-*, o<digit> and openai/* go to OpenAI; everything else stays Anthropic. Ids in MODELS stay plain, so the picker, saved choices and validation are unchanged.
  • buildModel in the new provider.ts (no Workers imports, so it tests under Node) builds the model through @ai-sdk/openai on the Responses API, the one that returns reasoning summaries. A missing key is a plain error in the chat.
  • turnSettings sends OpenAI reasoningEffort (our four levels map one to one, and Sol and Astra support all four), reasoningSummary: 'auto' and store: false. Anthropic settings are unchanged.
  • History stays provider-neutral: the existing forMemory already drops reasoning before saving, and store: false means we replay history ourselves rather than point at items held at OpenAI. That is what makes switching model mid-chat safe.
  • gpt-6.1-sol and gpt-6-astra added to MODELS in wrangler.jsonc. MODEL (the default) stays Claude.

Alternatives rejected. OpenAI Agents SDK (a second agent runtime next to Mastra: tools, memory and streaming twice over). OpenRouter or another gateway (another account and middleman for no gain with one extra provider). Chat Completions API (no reasoning summaries). A provider: prefix on ids (breaks saved Claude ids, and nothing else in the repo does it).

Security. OPENAI_API_KEY is a Worker secret, set by the deploy workflow from a repo secret, never logged or committed, handled like the Anthropic key. store: false means OpenAI keeps no conversation state, though OpenAI may keep API data for up to 30 days for abuse monitoring unless the account has zero data retention. Use a project key with a monthly spend limit.

Rollout. 1) Merge: nothing changes for Claude chats. 2) Chris adds the OPENAI_API_KEY repo secret and applies the workflow patch. 3) Deploy, with Chris's go-ahead. 4) Live check below. Rollback: remove the GPT entries from MODELS and push. Chats that saved a GPT model fall back to the default (resolve() already does this). No data migration either way.

Tests written first

These were written and seen failing (providerFor and provider.ts did not exist) before any code. Two checks I added while building, after reading what Mastra sends: the null-optionals test, and the switching test.

The OpenAI tests run the real @ai-sdk/openai client against a fake endpoint that records the request and streams a scripted reply, so they check what we would actually send, not a mock of our own code.

What Mastra does to tool schemas

Optional fields (timeout_seconds, visibility, id) are sent to OpenAI as required-but-nullable, and tools are sent with strict: false. So GPT may answer null for an optional field; test 11 proves our tools accept that.
