Evidence pack

Cathy on your ChatGPT plan

RFC

Problem. Chris wants Cathy's GPT chats to count against his ChatGPT plan rather than bill the OpenAI API.

How it works. OpenAI's Codex CLI signs in with a ChatGPT account (OAuth with PKCE, using Codex's public client id) and sends normal Responses API requests to chatgpt.com/backend-api/codex/responses, with the account token and a few headers. Cathy does the same. The design follows the open-source opencode plugin that does this, read line by line.

Design.

  • Picker. New ids chatgpt/gpt-6.1-sol and chatgpt/gpt-6-astra, labelled "(ChatGPT plan)", next to the API ones. Same model, different bill, so Chris chooses each time. A plan model never falls back to the API key, and an API model never uses the plan.
  • Sign-in (chatgpt-oauth.ts). Admin → ChatGPT plan → Start → sign in → the browser lands on a localhost page that can't load (that's Codex's fixed redirect) → paste that address back. A one-time state (compared in constant time) ties the paste to the sign-in Cathy started; it's single use and expires after 10 minutes.
  • Token store (chatgpt-vault.ts, chatgpt-account.ts). A dedicated Durable Object, ChatGPT "main". See Security.
  • Requests (chatgpt-fetch.ts). A custom fetch given to the existing OpenAI model: rewrites the body for the backend (store: false, streamed, ids and server references stripped, system → developer, encrypted reasoning kept), adds the token and Codex headers, and the chat id as the prompt-cache key. On a 401 it refreshes once and retries. A spent plan becomes "Your ChatGPT plan's usage limit is used up. It resets in about…".
  • Admin page (admin/src/chatgpt-ui.ts). Status (email and plan), connect, a "Send test" button that shows exactly what ChatGPT answers, and disconnect.

Alternatives rejected. Running Codex CLI in the box (the ai-sdk-provider-codex-cli route): Codex then runs its own tools and agent loop instead of Cathy's, and the sign-in would sit in the box where any command could read it. The opencode plugin as a dependency: it's built for opencode, uses Node file APIs, and rewrites prompts for opencode's tool names. Storing tokens in D1 or a Worker secret: D1 is shared with chats and artifacts and readable by more code; secrets can't be updated at runtime, and the refresh token rotates. A real redirect to admin: Codex's client only allows its localhost redirect.

Security: where the token lives

  • Only in the ChatGPT Durable Object's storage, encrypted at rest by Cloudflare. Not in D1, R2, a secret, a log, Cathy's box or any chat.
  • Nothing on the network can reach it. The object has no fetch handler. Only the Cathy Worker's own code calls it, through a binding. The Cathy Worker itself has no public address, and admin, the only way in, is behind Cloudflare Access.
  • The refresh token, PKCE verifier and id token never leave the object. The only thing that does is a short-lived access token, handed to the code making the request. The API returns status (email, plan) and the test reply, never a token or the account id (tested).
  • Token only to chatgpt.com. The fetch refuses any other host, plain http, odd ports or credentials in the URL before it even asks for the token, and never follows redirects (tested).
  • Cathy never sees it. It isn't in her context, her tools or her box's environment (the box only gets the GitHub token), and she has no tool that touches the ChatGPT routes.
  • No logging. Nothing logs the token, account id or messages. Error messages name the status code, never the request or response body, which can echo secrets (tested).
  • Cross-site requests. Changing routes only accept application/json, which a form on another site can't send, and they sit behind Access anyway.
  • Refresh races. ChatGPT rotates the refresh token, so two refreshes at once would kill the sign-in. Refreshes run one at a time (singleFlight), and the new token is saved before it's used. A dead refresh token wipes the sign-in and says to reconnect. A temporary failure keeps it.
  • Page safety. The admin page puts server text on the page only as text, never as HTML (tested with a hostile message in a real browser).
  • Disconnect deletes everything stored.

Honest risks. This is Codex's sign-in, not an official API for other apps. It could stop working without notice, and I can't confirm OpenAI's terms cover it (the opencode plugin says "personal development use", and this is one person's use). chatgpt.com may refuse requests from Cloudflare's network. My box gets 403 from it, so the first real sign-in is the real test. Usage comes out of the same limit as ChatGPT.

Rollout and rollback

Merge: nothing changes for existing chats. No secrets needed, and the new Durable Object is created on deploy. Then admin → ChatGPT plan → connect → Send test. Rollback: Disconnect, and/or remove the chatgpt/ entries from MODELS. Chats on them fall back to the default model.
